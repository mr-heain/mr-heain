## 🎯 PROBLEM STATEMENT

### Current Problems:
1. **File Sharing Limitations**
   - Cloud storage services (Google Drive, OneDrive) require internet connectivity and uploading files to external servers
   - Size limits on messaging apps (WhatsApp: 100MB, Telegram: 2GB)
   - Privacy concerns—files stored on third-party servers
   - Expensive for bulk file transfers

2. **Device-to-Device Transfer Challenges**
   - AirDrop only works between Apple devices
   - USB cable transfer is tedious and not always available
   - Email has attachment size restrictions (typically 25MB)
   - Existing solutions (Snapdrop, Send Anywhere) are closed-source or paid

3. **Local Network Unused Potential**
   - Most devices on the same WiFi network can't efficiently share files directly
   - No easy, privacy-first alternative exists for developers/students

### Real-World Impact:
- Students need to share project files, code, documents without uploading to cloud
- Teams working offline (workshops, labs) need instant file transfer
- Privacy-conscious users want data to stay local
- No existing open-source, browser-based P2P solution that's easy to use

---

## 💡 BASE IDEA

**Core Concept:** Build a **web-based, decentralized file sharing platform** where two or more devices can:
- Connect directly to each other (peer-to-peer, no server involvement in file transfer)
- Share files without uploading to a central server
- Work within the same local network or across the internet (via WebRTC signaling)
- Access through a web browser (no installation needed)

**Key Innovation:** Files transfer directly between devices using **WebRTC Data Channels**. The server only acts as a "matchmaker" to help devices find each other—it never touches the actual files.

## 🔧 HOW THE PROJECT WORKS

### System Architecture

```
┌─────────────────────────────────────────────────────────┐
│                   WEB BROWSER INTERFACE                  │
│  (React App - Drag-Drop, Progress, File List)           │
└────────────────────┬────────────────────────────────────┘
                     │
          ┌──────────┴──────────┐
          │                     │
    ┌─────▼─────┐         ┌────▼──────┐
    │  Device A │         │  Device B  │
    │ (WebRTC)  │         │ (WebRTC)   │
    └─────┬─────┘         └────┬───────┘
          │                    │
          └────────┬───────────┘
                   │
          (P2P File Transfer)
          (No Server Involved)
          
          Signaling Server
          (Node.js - Only for initial connection)
          └─ WebSocket handshake
          └─ Room management
          └─ Device discovery
```

### Step-by-Step Process

#### **1. Creating a Room (Device A - Sender)**
```
User A opens web app
  ↓
Clicks "Create Room"
  ↓
System generates unique room code (e.g., ABC123)
  ↓
Room stored in server database
  ↓
Device A waits for incoming connections
```

#### **2. Joining a Room (Device B - Receiver)**
```
User B enters room code (ABC123)
  ↓
Browser connects to signaling server
  ↓
Server identifies both devices in same room
  ↓
Server sends WebRTC connection info (SDP offer/answer)
  ↓
Devices establish direct P2P connection
```

#### **3. File Transfer (Direct P2P)**
```
User A drags file onto web app
  ↓
File is split into chunks (1MB each)
  ↓
Chunks sent directly to Device B via WebRTC Data Channel
  ↓
No server involvement in file transfer
  ↓
Device B receives chunks and reassembles file
  ↓
Transfer complete with checksum verification
```
